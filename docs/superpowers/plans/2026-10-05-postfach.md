# Postfach (Plan 3c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die Routine R3 wertet zweimal täglich das Gmail-Postfach aus: gesendete Bewerbungen werden als *Beworben* verbucht, eindeutige Antworten (Absage, Einladung, Challenge, Angebot) direkt als Ereignis angelegt, unklare als Vorschlag im Dashboard abgelegt, und auf Rückfragen entsteht ein Antwortentwurf. Jede Mail wird nur einmal verarbeitet.

**Architecture:**
- Gmail liest die Routine selbst über den Gmail-Konnektor (Suchen, Threads lesen, Antwortentwurf per `replyToMessageId` – reiner Text, kein Anhang). Der Pi speichert nur Ergebnisse.
- Migration `00007` ergänzt `applications.gmail_thread_id` und legt `status_suggestions` und `processed_mails` an.
- Agent-API: offene Bewerbungen inkl. erlaubter nächster Ereignisse und Mail-Betreff, Ereignis anlegen (dieselbe Übergangsprüfung wie die Oberfläche), Thread-ID setzen, Vorschläge anlegen, verarbeitete Mails prüfen/merken.
- Oberfläche: Dashboard-Box „Vorschläge des Agenten“ mit Übernehmen (legt das Ereignis an; bei nicht zugeordneten Vorschlägen Auswahl der Bewerbung) und Verwerfen.

**Tech Stack:** Go 1.27, PostgreSQL 17, goose, sqlc, oapi-codegen (strict), kin-openapi; Angular 22, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-03-agenten-automatisierung-design.md` – „Datenmodell → status_suggestions, processed_mails“, „Agent-API“ (`POST /applications/{id}/events`, `POST /suggestions`, `GET/POST /processed-mails`), „Oberfläche → Dashboard“, „Routinen → R3“.

**Umgebung (Windows):** vor Go-/task-Befehlen `export PATH="/c/Program Files/Go/bin:$HOME/go/bin:$PATH"`; Docker Desktop läuft (falls nicht: BLOCKED melden, nicht selbst starten); Commits ohne Attributionszeilen; Branch `feature/postfach` (legt der Controller an).

```sql
-- +goose Up
ALTER TABLE applications ADD COLUMN gmail_thread_id text;
CREATE UNIQUE INDEX applications_gmail_thread ON applications (gmail_thread_id) WHERE gmail_thread_id IS NOT NULL;

CREATE TABLE status_suggestions (
    id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    application_id uuid REFERENCES applications (id) ON DELETE CASCADE, -- NULL = nicht zugeordnet
    suggested_type text NOT NULL CHECK (suggested_type IN (
        'Vorgemerkt', 'Beworben', 'ScreeningGespraech', 'ChallengeErhalten', 'ChallengeAbgegeben',
        'Interview', 'Kennenlerntag', 'AngebotErhalten', 'AngebotAngenommen', 'AngebotAbgelehnt',
        'Absage', 'Zurueckgezogen', 'KeineRueckmeldung')),
    occurred_on    date NOT NULL,
    due_on         date,
    reason         text NOT NULL,
    mail_subject   text,
    mail_from      text,
    mail_url       text,
    state          text NOT NULL DEFAULT 'offen' CHECK (state IN ('offen', 'angenommen', 'verworfen')),
    created_at     timestamptz NOT NULL DEFAULT now(),
    decided_at     timestamptz
);
CREATE INDEX status_suggestions_open ON status_suggestions (created_at) WHERE state = 'offen';

CREATE TABLE processed_mails (
    gmail_message_id text PRIMARY KEY,
    application_id   uuid REFERENCES applications (id) ON DELETE SET NULL,
    outcome          text NOT NULL,
    processed_at     timestamptz NOT NULL DEFAULT now()
);

-- +goose Down
DROP TABLE processed_mails;
DROP TABLE status_suggestions;
DROP INDEX applications_gmail_thread;
ALTER TABLE applications DROP COLUMN gmail_thread_id;
```

- [ ] **Step 1: Spec**

Schemas: `OpenApplication` (id, company_name, company_website, position_title, status, contact_email, gmail_thread_id, documents_state, gmail_draft_at, mail_subject, allowed_events: [EventType]), `AgentEventInput` (= `NewEvent`-Felder; `note` max. 1000), `GmailThreadInput` (`gmail_thread_id`: 1–100 Zeichen, Pattern `^[A-Za-z0-9_-]+$`), `SuggestionInput` (application_id optional uuid, suggested_type EventType, occurred_on date, due_on date optional, reason 1–1000 `\S`, mail_subject ≤ 300 ohne CR/LF, mail_from ≤ 300 ohne CR/LF, mail_url ≤ 500 Pattern `^https://mail\.google\.com/\S*$`), `Suggestion` (alle Felder + company_name, position_title, state, created_at), `ProcessedMailInput` (gmail_message_id 1–200 `^[A-Za-z0-9_-]+$`, application_id optional, outcome 1–200), `ProcessedMail`, `SuggestionAccept` (application_id optional).

`Application` bekommt `gmail_thread_id`.

Agent-Pfade (Token, Tag `Agent`):
- `GET /api/agent/applications/open` → `[OpenApplication]`
- `POST /api/agent/applications/{id}/events` (Body `NewEvent`) → 201 `Event`; unerlaubt → wie UI (422/409 je nach vorhandenem Mapping)
- `PUT /api/agent/applications/{id}/gmail-thread` (Body `GmailThreadInput`) → 204
- `POST /api/agent/suggestions` (Body `SuggestionInput`) → 201 `Suggestion`
- `GET /api/agent/processed-mails/{messageId}` → 200 `ProcessedMail` / 404
- `POST /api/agent/processed-mails` (Body `ProcessedMailInput`) → 201 neu, 200 schon vorhanden

Achtung Pfadkonflikt: `/api/agent/applications/open` vs. `/api/agent/applications/{id}/…` – `open` ist kein UUID; Go-ServeMux bevorzugt das spezifischere Muster. Testen.

Oberflächen-Pfade (Tag `Suggestions`):
- `GET /api/v1/suggestions` → offene Vorschläge
- `POST /api/v1/suggestions/{id}/accept` (Body `SuggestionAccept`) → 200 `Application`
- `POST /api/v1/suggestions/{id}/dismiss` → 204

`task generate:api`, `task generate:client`.
